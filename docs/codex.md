Codex vs Claude isolation (fixed 2026-10-28; a Codex session from the app showed the folder's old Claude transcript): a session the app launched Codex in is keyed `codex:<session>` from the moment it is created (`noteSessionAgent` + `markSessionAsNew` run BEFORE the launch check, the hint survives a restart via the saved tmux config), also while no codex process is seen yet; `ensureConversationLoaded` never scans a Claude projects dir for a Codex session or a just-created one; cwd fallbacks (`waitForSessionInCwd(cwd, ms, agent)`, `resolveSessionByTmuxName`) only take the agent's own transcripts. Before the first prompt a Codex session has no rollout and shows an empty chat. First message: Codex creates the rollout as the turn starts; an `fs.watch` on today's `sessions/YYYY/MM/DD` of each Codex home with an unmapped session (only new rollout names count, debounced, dropped once all are mapped) plus send nudges at 1.5 / 3.5 / 6.5 s (`requestRefresh` re-runs after an in-flight refresh) map it in about a second (probe: 1.1 s).
Start-up prompts ("Trust this folder?", Codex in an untrusted GIT folder, also with the bypass flag; Claude's own in any new folder; Claude's Bypass Permissions warning, which can follow it): `agents/trust.ts` parses them into a choice `kind: 'trust'` (yes is always option 0, no option 1; `trustLayout` = where the rows really are, daemon only) that `get_highlights` carries as `Question.kind` and the web shows as `components/TrustPromptCard.tsx` (old clients: the plain question block, and it still works); the watcher notes it from captures (get_highlights, Herald's listing, and its own bounded start-up captures: agents started < 10 min ago without a transcript, 2 per refresh, in-flight guarded, stop once the screen is ready) and reports the session as waiting (`TRUST_PROMPT_ACTIVITY`, status-change on each edge and when the next prompt follows). The parser needs the hint line as the LAST thing on screen: after "No, exit" the old dialog stays visible above a shell prompt. Only the user answers it: `InputInjector.sendChoice` refuses a start-up prompt unless `answerTrust` (only the `send_choice` handler passes it), `send_input` is refused while it (or any Codex choice box) is on screen (reason `trust` / `choice`, wire code `prompt_waiting`; before, the paste was dropped and its Enter picked the selected row, which on Claude is "No, exit"), babysit (`isPermissionChoice`), Herald (`propose_input` option refused, `answer_choice` re-check) and auto-approval never answer it. `promptKind: 'trust'` on `send_choice` = send nothing if the prompt has gone; after the keys the injector polls up to 3 s and reports failure if the same prompt is still up. Keys, live: Codex Yes = "1" + Enter ("1" only selects), No = "2" (Back to Agent Command Center) + Ctrl+C (quits Codex: an untrusted folder has no working session; Esc there shows a composer whose messages only queue).
